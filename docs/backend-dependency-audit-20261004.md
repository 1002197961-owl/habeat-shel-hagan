## Affected by the paused project

- `app/library/page.tsx` loads the shared catalog from `/rest/v1/song_catalog`. It initializes the three `DEMO_TRACKS` immediately, aborts the request after 8 seconds, and displays the local fallback notice on request failure.
- `lib/catalog.ts` identifies the paused project and retrieves approved remote recordings from `/storage/v1/object/authenticated/song-audio/…`. Such remote recording retrieval depends on the backend being available.

## Independent of this backend

- The three original instrumental exercises are synthesized by `lib/audio.ts` using local Web Audio scores.
- Narration and word highlights use `data/narration.json`, `lib/narration.ts`, `hooks/useNarration.ts` and 13 same-origin `/audio/*.mp3` assets.
- The SENOSEN input path is local Web MIDI in `app/turn-taking/page.tsx` and `lib/instrumentInput.ts`; feedback is generated by `lib/turnTone.ts`. Diagnostic JSON is downloaded locally.
- Reconstructed Magic Song rehearsal imports the static `DEMO_TRACKS` constants and calls local `playMusic`. Importing catalog constants does not invoke the backend. The gated sung player permits only approved same-origin `/audio/magic-song/` files; its empty manifest starts no audio request.
- The locked Gate source has no runtime dependency on this Supabase project. Its library renders local `MOCK_SONGS`; that is not evidence of real audio playback.

The pause therefore does not inherently disable MIDI, narration/highlights or built-in instrumentals. This is not a guarantee of full offline website operation: the site's own files must still load. It also does not establish physical SENOSEN compatibility.

## Verification boundary

This code-only dependency analysis does not certify backend availability, browser interaction, or physical hardware behavior. Those require separate checks.
